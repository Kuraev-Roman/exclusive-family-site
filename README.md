# EXCLUSIVE FAMILY — сайт семьи

Сайт на Node.js/Express: авторизация по нику и паролю (аккаунты создаёт только
админ), раздел «Кражи» (сообщения с изображением админу), «Дни рождения»
(ручное добавление + импорт Excel/CSV, фото участников, блок «сегодня» виден
без входа), «Новости» (текст/фото/видео — копипаст с телеграм-канала),
«Интерактивы» (голосования — создаёт админ, голосуют участники), «Вступить в
семью» (заявка без регистрации + шаблон условий) и раздел с шутками про
миньонов. Оформление: чёрно-золотая тема с анимированным фоном из частиц.

## Запуск локально (через VS Code / терминал)

1. Установи [Node.js](https://nodejs.org/) версии 18 или новее.
2. Открой папку `exclusive-family-site` в VS Code.
3. В терминале VS Code:

   ```bash
   npm install
   npm start
   ```

4. Открой в браузере: **http://localhost:3000**

При первом запуске автоматически создаётся:
- аккаунт администратора: **логин `admin`, пароль `admin123`** (смени его в
  «Профиле» после первого входа),
- таблица дней рождения — импортирована из `Дни_рождения_Exclusive.xlsx`
  (66 записей).

## Роли пользователей

- **Участник (member)** — обычный аккаунт, видит все публичные разделы, может
  голосовать и писать в «Кражи».
- **Зам. администратора (deputy)** — дополнительно получает доступ к
  повседневному управлению контентом: дни рождения, новости, альбом,
  интерактивы, заявки, FAQ, входящие «Кражи». **Не может** создавать/удалять
  аккаунты и менять настройки (соцсети, условия вступления) — это только у
  главного админа.
- **Администратор (admin)** — полный доступ ко всему, включая создание
  аккаунтов, назначение ролей и настройки сайта. Аккаунт `admin` (созданный
  автоматически при первом запуске) нельзя удалить или понизить в роли — это
  подстраховка, чтобы сайт нельзя было случайно оставить без главного админа.

Роль назначается в `/admin/users` — там же настраиваются публичные контакты
(имя-должность вроде «Глава семьи» + ссылка на телеграм) для страницы
`/contacts`, которые видят обычные участники, если захотят написать лично.

## Как это устроено

- **Регистрации на сайте нет** — только админ создаёт аккаунты
  (`/admin/users`). Гость, который хочет попасть в семью, оставляет заявку на
  `/join` без создания аккаунта — админ видит её в `/admin/applications` и
  сам решает, выдавать ли доступ.
- **Условия вступления** на странице `/join` — черновой шаблон
  (ранг от 3★, активность от 800, донат от 800 и т.д.) — при необходимости
  подправь текст в `views/join.ejs`, я это составил ориентировочно, поменяй
  цифры/пункты под реальные правила семьи.
- **Дни рождения**: у каждой записи теперь может быть фото — либо участник
  сам загружает аватар в профиле (и он подставится в запись с совпадающим
  ником), либо админ прикрепляет фото прямо в `/admin/birthdays`. Тех, у кого
  сегодня день рождения, без входа видно на главной и на `/birthdays`.
- **Интерактивы**: админ создаёт вопрос + варианты (+ картинку) в
  `/admin/interactives`. Результаты голосования видно всем, а голосовать
  может только вошедший участник, один голос на голосование.
- **Новости**: сюда вручную переносится контент из телеграм-канала —
  текст + фото (можно несколько) + ссылка на видео. Прямого автоматического
  парсинга канала пока нет — если пришлёшь ссылку/юзернейм канала, помогу
  прикрутить автоматическую подгрузку постов.
- **Дизайн**: анимированный фон из золотых частиц (`public/js/particles.js`,
  канвас, без внешних гиф-файлов — лёгкий и не тормозит), крупная типографика,
  градиентные акценты, объёмные карточки с ховер-эффектами.
- **Хранилище данных**: `data/db.json` — простой JSON-файл, без установки
  СУБД, этого достаточно для локального просмотра. Перед выкладкой в интернет
  стоит перейти на настоящую БД (SQLite/Postgres) и облачное хранилище для
  фото — скажи, когда дойдёт до этого шага.

## Постоянная база данных (Neon, бесплатно навсегда, без карты)

Без этого шага база (аккаунты, дни рождения, кражи и т.д.) хранится в обычном
JSON-файле на диске Render — а бесплатный диск Render **стирается при каждом
передеплое или перезапуске сервера**. Для 10-20 человек это ещё терпимо, но
если хотите завести 100+ реальных аккаунтов — обязательно подключите Neon,
иначе люди периодически будут терять доступ.

**Как подключить:**

1. Зайди на **neon.tech** → зарегистрируйся (email или GitHub, карта не нужна)
2. **Create a project** → любое название, регион ближе к вам
3. На странице проекта найди **Connection string** (обычно сразу показывается
   после создания) — она выглядит примерно так:
   ```
   postgresql://user:password@ep-xxx-xxx.us-east-2.aws.neon.tech/neondb?sslmode=require
   ```
   Скопируй её целиком.
4. На **Render** → твой сервис → **Environment** → **Add Environment Variable**:
   - Key: `DATABASE_URL`
   - Value: скопированная строка подключения
5. Сохрани — Render передеплоит сервис, и при следующем запуске сайт сам:
   - создаст нужную таблицу в Neon,
   - перенесёт туда все текущие данные,
   - дальше будет сохранять туда каждое изменение (с секунды на секунду, а не
     мгновенно — это нормально)

После этого аккаунты, дни рождения и все остальные данные **переживут любой
передеплой или перезапуск сервера** — то есть можно спокойно заводить сколько
угодно реальных аккаунтов (0.5 ГБ бесплатного лимита Neon — это очень много
для текстовых данных, туда влезут тысячи аккаунтов).

**Важно:** фото/видео (аватарки, альбом, кражи, новости) всё равно продолжают
храниться на диске Render и подчиняются его ограничениям (могут сброситься
при передеплое) — Neon решает только про базу данных (тексты, аккаунты,
структура), а не про сами файлы. Если нужно и файлы сделать надёжными —
это отдельный следующий шаг (внешнее файловое хранилище).

Если переменную `DATABASE_URL` не задавать — сайт как и раньше работает на
локальном JSON-файле, ничего не ломается, это полностью необязательный шаг.

## Автоимпорт новостей из Telegram-канала

Сайт умеет сам забирать новые посты (текст, фото, видео) из вашего телеграм-канала
и публиковать их в разделе «Новости» — без ручного копипаста.

**Важно про ограничение Telegram:** бот не может сам "зайти" в приватный канал
по инвайт-ссылке — это техническое ограничение платформы. Владелец канала
обязательно должен **вручную добавить бота администратором**.

**Как настроить:**

1. В Telegram напиши **@BotFather** → `/newbot` → придумай имя и юзернейм бота
   → получишь **токен** (строка вида `123456:ABC-DEF...`)
2. Зайди в свой канал → **Управление каналом → Администраторы → Добавить
   администратора** → найди своего бота по юзернейму → добавь с любыми правами
   (достаточно чтения сообщений)
3. На **Render** → твой сервис → **Environment** → **Add Environment Variable**:
   - Key: `TELEGRAM_BOT_TOKEN`
   - Value: токен из шага 1
4. Сохрани — Render сам передеплоит сервис с новой переменной

После этого сайт каждые 15 секунд проверяет канал и автоматически публикует
новые посты (с фото/видео) в разделе «Новости» с пометкой источника Telegram.
Старые посты, которые уже были в канале до подключения бота, не подтягиваются —
только новые, отправленные после настройки.



Проект уже готов к деплою — внутри есть `render.yaml` и git-репозиторий с
первым коммитом. Render даёт бесплатный веб-сервис без привязки карты
(единственный минус — «засыпает» после 15 минут без запросов и оживает
секунд за 30-60 при следующем заходе, для «просто посмотреть» это не проблема).

1. **Залей код на GitHub** (нужен бесплатный аккаунт github.com):
   ```bash
   cd exclusive-family-site
   git remote add origin https://github.com/ТВОЙ_НИК/exclusive-family-site.git
   git branch -M main
   git push -u origin main
   ```
   Если ещё не создавал репозиторий — сделай это на github.com («New repository»,
   можно приватный) и вставь его адрес в команду выше вместо `ТВОЙ_НИК/...`.

2. **Зайди на [render.com](https://render.com)** и зарегистрируйся через GitHub
   (карта не нужна).

3. **New → Web Service** → выбери свой репозиторий `exclusive-family-site`.

4. Render сам подхватит настройки из `render.yaml`
   (Build Command: `npm install`, Start Command: `npm start`, план — Free).
   Если не подхватит — впиши эти команды вручную.

5. Нажми **Create Web Service** — через пару минут получишь ссылку вида
   `https://exclusive-family-site.onrender.com` — можно скидывать кому угодно.

**Важно про бесплатный план:** диск на нём временный — при каждом новом
деплое (и иногда при пробуждении после сна) файл `data/db.json` и загруженные
фото/скриншоты могут сброситься к начальному состоянию (только исходные 66
дней рождения и админ `admin`/`admin123`). Для «показать вживую» этого более
чем достаточно; когда решишь оставить сайт насовсем — подключим постоянное
хранилище (например бесплатный тариф Render Disk или внешнюю БД) и домен.



- Разместить сайт в интернете (хостинг + домен) вместо localhost.
- Перевести хранилище на настоящую БД.
- Прикрутить автопарсинг новостей/мемов из телеграм-канала (нужна ссылка на
  канал и, вероятно, Telegram Bot API токен).
- Добавить полноценный видеоплеер вместо ссылки на видео.
- Уведомления админу (например в Telegram) при новой заявке/сообщении в
  «Кражах»/голосовании.
